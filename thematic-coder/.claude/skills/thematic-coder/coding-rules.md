# Coding Rules — Thematic Coder

## Domain

Mobile AI usage: governance, prompting discipline, and operational practices for phone-based AI work.

This codebook was developed from the *AI Phone Command Playbook* — a practitioner document describing how to use AI tools effectively and safely on mobile devices.

## Coding mode

Hybrid. The 15 seed codes in `codebook.md` are the starting point. Expand only when source evidence describes a concept genuinely not covered by existing codes.

## Codeable unit

A paragraph or continuous section that expresses a discrete practice, rule, observation, or constraint related to mobile AI usage.

Do not code individual sentences in isolation unless they stand alone as a complete, self-contained practice statement.

## Quote rules

1. Quotes must be exact, contiguous substrings of the source paragraph. No paraphrasing.
2. No ellipses or editorial markers (e.g. `[...]`, `...`).
3. The quote must stand alone as evidence for the assigned code — a reader who has not seen the source should confirm the code from the quote alone.
4. Prefer the shortest quote that fully supports the code. Do not quote entire paragraphs when a single sentence is sufficient.
5. Preserve original capitalisation, punctuation, and spelling.

## Code assignment rules

1. Assignment must be defensible from the quote alone.
2. Apply the inclusion rule for each code: the evidence must directly describe the relevant concept in mobile AI work.
3. Apply the exclusion rule for each code: do not code generic productivity advice unless it contains an explicit mobile-AI control, boundary, or governance mechanism.
4. A quote may receive multiple codes if it genuinely evidences multiple distinct concepts — produce one row per code.
5. The same quote cannot receive the same theme/sub_theme combo twice.
6. When two codes are plausible, choose the more specific one.

## New code creation

Create a new code only when:
- The evidence describes a concept not covered by any of the existing seed codes
- You can write a clear definition, inclusion rule, and exclusion rule
- You have at least one verbatim example quote from the source

New code format (must match existing codebook format exactly):
```
## [Code name]
- **Definition:** [what this code captures]
- **Sub-codes:** [sub-code names, or "None"]
- **Inclusion rule:** Use when evidence directly describes [concept] in mobile AI work.
- **Exclusion rule:** Do not use for generic productivity advice unless it contains an explicit mobile-AI control, boundary, or governance mechanism.
- **Example quote:** "[verbatim quote from source]"
```

## Evidence discipline

These rules align with the Subztevo Prompt OS evidence discipline:

- Separate observed facts from inference. Code what the source states, not what it implies.
- Do not invent themes not present in the source.
- Do not turn one example into a universal rule.
- Mark ambiguous passages as `[NEEDS HUMAN REVIEW]` in the notes column rather than forcing a code.
- Do not assign a code if the inclusion rule is not clearly met.

## Quality checklist (per row)

Before finalising each row, confirm:
- [ ] Quote is verbatim (exact substring of source)
- [ ] Quote is contiguous (no ellipses, no splicing)
- [ ] Code assignment is defensible from the quote alone
- [ ] Inclusion rule is met
- [ ] Exclusion rule is not triggered
- [ ] No duplicate theme/sub_theme combo on this quote
